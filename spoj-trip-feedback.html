Trip feedback, prioritised

Feedback from the last trip, grouped into 13 items and ranked by impact on the core flow (find a connection, then ride it) and on the honest-data principle, against effort in the current codebase. Effort: S under a day, M a few days, L a week or more, XL needs a data source we don't have yet.

P0Now: bugs and cheap trust wins

Small fixes for things that broke or misled you during the trip. Ship these as one batch.

1Train in station covers the station touch targetS · bug

The vehicle marker sits on top of the stop, so you can't tap the stop. Fix the hit order or offset in LiveMap.web.tsx. #6 changes the train marker anyway, so this fix may come out of that work.

2Stop highlight in Odchody for low-height stop cardsS · bug

Follow-up to the focus and highlight fix in def8715: collapsed or short cards lose the highlight.

3Persist the tracked journey across reloadS

Mobile browsers kill backgrounded PWAs all the time, so today you lose Jazda mid-ride. Store the tripID and selection in localStorage (the same pattern as search selections in useTransitData.ts) and restore it if the trip hasn't ended.

4Town names for regional bus stops and train stationsS

The Ubian payloads already carry stopCity, so this is mostly rendering. Show it for regional and train stops, and wherever the stop name doesn't already contain the town. This removes ambiguity in search results.

5Location permission on load, with an explainerS–M

Show a short "what Spoj does" screen with a Share location button. Remember the first grant, and on later visits request it on load so the browser can re-prompt without the explainer. Without a grant, search falls back to the Odkiaľ-first flow in #7.

P1Next: the honest-data principle and journey planning

The highest product value. The first item is about trust and is cheap to start, so it leads.

6Trains: show "last reported", not "is here"S → L, in two steps

  • 6a, glyph (S–M): mark the stations where the train position refreshes, and label the train with "reported at X, Y min ago". That is enough to stop implying a live position.
  • 6b, track section (M–L): instead of a single point, draw the stretch of track between the last report and the next report station. trip_stops?withRoute already returns route geometry, so the work is slicing the line between two stations and styling it.
  • Countdown to arrival based on the user's location builds on 6a and can wait.

7Two-row search: Odkiaľ / KamM

The placeholder becomes "Hľadať spoj". Tapping it expands into two rows: Odkiaľ on top, Kam focused. Without a location grant, Odkiaľ gets focus first. Today the field is a single "Kam?" with a separate Odkiaľ row, and /navigation/connections already takes both ends.

8Search by location or pinM · after #7

This is an input mode of the same two fields: "pick on map" or "current location" as Odkiaľ or Kam. Build it once #7 exists so it isn't designed twice.

9Departures from a journey stop at the tracked arrival timeM · needs a spike

Useful for planning transfers. planned_departures is currently called without a time parameter. Check first whether Ubian accepts a start time. If it doesn't, a limit plus client-side filtering works only for arrivals in the near future.

P2Later: map scale and personalisation

10Zoom-out: trains and long-distance only, stops into city targetsM–L

Today, when you're zoomed out beyond what one request covers, the map is intentionally empty. Instead, request only trains and long-distance or regional vehicles. Don't bundle stops: collapse them into one target per city, where a tap shows the main train and regional bus hubs, or zooms in. This depends on #4 for city grouping and may need different upstream filters (cityID, radius).

11Saved placesL

  • Basic saved places first (name and location). These also seed the Odkiaľ/Kam suggestions in #7.
  • Annotating direct connections in Odchody needs the stop list for each departure, which means N extra trip_stops calls. Cache them per trip and limit them to visible cards.
  • Per-place stop radius and a stop allow/deny list come last. This is power-user tuning.

P3Research first: offline

12Offline access: local stops, timetables, approximate connectionsXL

The service worker only caches the app shell, and every endpoint we use is live and undocumented, with no bulk export. Doing this properly needs a timetable source (GTFS or CIS JŘ exports) plus local routing, which makes it a project of its own. Start with a spike on data availability. A cheap interim step is caching the last stops and departures responses for saved places.

13"Timetables last updated" messageS · with #12

Trivial to build, but it only means something once there is offline data. Ship it together with #12.
