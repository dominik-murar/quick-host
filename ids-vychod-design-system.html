One network.
One sunrise.

A design-system sketch for the integrated public-transport app of the Košice and Prešov regions — city trams and trolleybuses, regional buses and trains under one fare. One shared token core, three fully native shells: SwiftUI, Jetpack Compose and the web.

R63823 701Os 8813N1

Concept work. Line numbers, operators and fares are illustrative — not official IDS Východ data or branding.

01 · Principles

What the app has to be good at

⏱ Time is the hero

Every screen answers "when?" first. Minutes-to-departure are the largest number on screen, tabular figures, real-time vs. scheduled always distinguishable without color.

🧭 Native first, brand second

Navigation, sheets, gestures, typography and haptics belong to the platform. The brand lives in the network itself: line badges, mode colours, the ticket, the map.

🤲 One-hand, one-glance

Primary actions in the thumb zone. Live Activities, widgets and lock-screen tickets mean most journeys never require opening the app.

📶 Works in Slanec, not just Košice

Rural coverage is patchy. Tickets, timetables and the last search are offline-first; live data degrades gracefully to "scheduled".

♿ Everyone rides

WCAG 2.2 AA minimum, largest text sizes supported, low-floor & step-free info as first-class data, Slovak / English / Hungarian / Ukrainian.

🎟 Honest fares

Show the total price before the pay button, recommend the cheapest valid ticket for the planned trip, never dark-pattern upsells.

Touch targets: 44 pt (iOS), 48 dp (Android), 24 px minimum / 44 px recommended (web, WCAG 2.5.8).

Shape & elevation are platform-owned

Tokens are semantic (shape.card, shape.sheet) and resolve per platform: iOS uses concentric continuous corners and Liquid Glass materials; Android maps to the Material 3 shape scale and tonal elevation; web uses 8–12 px radii with shadow elevation.

Motion

Vehicles interpolate smoothly between GPS pings (no teleporting), 150–250 ms UI transitions, springs on iOS, Material motion on Android. prefers-reduced-motion / Reduce Motion stop ticket animation loops and vehicle tweening.

04 · Components

The network vocabulary

Line badge

R63823701REXN1

R63823Os 472

Sizes sm / md / lg. Glyph variant used where the badge appears alone (map callouts, widgets). Shape differs per mode so colour-blind riders and greyscale e-ink signage still work. Text never truncates; long train numbers grow horizontally.

Anatomy

container (mode shape) · optional glyph · label (bold, tabular) · optional accessibility suffix.

VoiceOver / TalkBack label: "Električka R6" — never just "R6". Night lines add "nočná linka".

Do
Use the badge everywhere a line is referenced — departures, map, tickets, alerts.
Don't
Recolour badges for brand/marketing, or use mode colours for non-mode UI.

Rules

  • < 60 min → relative ("2 min", "teraz"); ≥ 60 min → clock time.
  • Real-time shown in green + pulsing dot + "naživo" text; scheduled in neutral text. Never colour alone.
  • Delay shows both new time and delta when tapped/expanded.
  • Cancelled rows stay visible with strike-through planned time and a suggested alternative.
  • Occupancy uses 3 bars + word (voľno / stredne / plno).
  • Rows update in place — no list jumps; VoiceOver announces only when a followed departure changes.

Live vehicle marker

Shape matches badge. Heading arrow appears when speed > 3 km/h. Stale position (> 90 s since ping) fades to 45 % with dashed outline and is labelled "posledná poloha pred 2 min". Clusters at low zoom show a mode-mixed count.

Data honesty

Positions are dead-reckoned along the route shape between pings and snapped to track. If a ping contradicts the estimate by > 150 m, ease to the new point over 600 ms rather than jumping. Never extrapolate beyond the next stop.

06 · Accessibility & inclusion

Non-negotiables

Perception

  • WCAG 2.2 AA, 4.5:1 text, 3:1 UI
  • Mode = colour + shape + glyph
  • Real-time = colour + dot + word
  • Map has a list-view equivalent

Operation

  • Dynamic Type AX5 / 200 % font scale without truncating times
  • Full VoiceOver, TalkBack, keyboard & Switch Control paths
  • No time-limited flows except the ticket itself

Mobility data

  • Step-free routing filter
  • Low-floor vehicle flag on every departure
  • Lift / escalator outage alerts at stations

Language

  • Slovenčina (default), English, Magyar, Українська
  • Stop names never translated
  • Layouts tested at +40 % string length

Low connectivity

  • Timetables cached per region
  • Tickets valid offline (signed, time-based QR)
  • "Offline · podľa CP" state, never a blank screen

Low-tech riders

  • Buy without an account (guest + receipt e-mail)
  • Senior/student discounts verified once
  • Large "Kúpiť lístok" path from app launch in 2 taps
07 · Tokens & delivery

One source, three outputs

Tokens are authored in the W3C Design Tokens format and compiled with Style Dictionary into Swift Color/ShapeStyle extensions, a Compose IdsTheme, and CSS custom properties. Three tiers:

  1. Primitive — raw values (blue.700, red.600).
  2. Semantic — intent (mode.tram, status.delayed, surface.raised). Light & dark resolve here.
  3. Platform — mapped onto native systems (Material color roles, iOS semantic colours). Components only consume tiers 2–3.

Components are specified once (anatomy, states, a11y labels, copy) and implemented natively: LineBadge in SwiftUI, @Composable LineBadge, and a <ids-line-badge> web component. Shared logic (fare engine, GTFS-RT parsing, ticket signing) lives in Kotlin Multiplatform; UI never does.

// tokens/semantic/mode.json
{
  "mode": {
    "tram": {
      "$type": "color",
      "$value": "{red.600}",
      "$extensions": {
        "ids.dark": "{red.400}",
        "ids.shape": "pill",
        "ids.glyph": "tram",
        "ids.a11yName": { "sk": "Električka", "en": "Tram" }
      }
    }
  }
}

// SwiftUI
LineBadge(line: .init("R6", mode: .tram))

// Compose
LineBadge(line = Line("R6", Mode.Tram))

// Web
<ids-line-badge mode="tram">R6</ids-line-badge>

Open questions for the next iteration

  • Validation model: QR on board validators, NFC (Apple/Google Wallet transit), or EMV contactless tap-in/tap-out with fare capping?
  • Do operators (DPMK, DPMP, regional carriers, ZSSK) provide unified GTFS-RT, or does IDS need to aggregate?
  • Co-branding rules on vehicles and stops — the app's mode colours should match physical signage.
  • Fare-zone map visualisation for regional users who think in towns, not zone numbers.
