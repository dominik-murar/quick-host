Spoj — repo structure & testing proposal

Splitting the 2,288-line app/index.tsx into feature modules with a pure, unit-tested domain core. Proposal — nothing changed yet.

Where it stands

Already duplicated across files: normalizeStopKey, coordinateDistance, modeColor. That's the clearest sign the domain logic needs one home.

Principles

  • app/ holds routes only. Every route file is a thin entry point (expo-router convention); no logic.
  • Pure core, thin React shell. Anything that doesn't need React goes into src/domain as plain TS. That's where most of the logic lives and most of the tests go.
  • Group by feature, not by kind. A feature folder holds its components, hooks and styles. Shared UI primitives go in src/ui.
  • Top-down files. Each file opens with its exported orchestrator; helpers follow (your AGENTS.md rule, already followed in most files).
  • One-way dependencies: features → data → api, and everything may import domain. domain imports nothing from React or the network.

Calls worth making explicit

  • Screen state as a reducer. The orchestrator's ~28 useStates allow impossible combinations (e.g. mode: 'departures' with a selected journey). A discriminated union removes those states, and the transitions become pure functions you can test: 
    type Screen =
  | { mode: 'departures'; focusedStop: DepartureItem | null }
  | { mode: 'search'; query: string }
  | { mode: 'results'; destination: Stop; selectedUid: string | null }
  | { mode: 'details'; selection: ConnectionSelection; backTo: 'departures' | 'results' };
    Animated values and gesture refs stay as local hook state in sheet/ and ride/.
  • Styles stay with their components. Shared tokens go in ui/theme/tokens.ts. Each component file defines its own light styles plus dark overrides through one createThemedStyles(light, dark) helper, replacing the single 280-line sheet.
  • components/ goes away. LiveMap moves into features/map. The .web.tsx platform-extension split still works there.
  • No barrel files, except one index.ts per feature that exposes its public component. Barrels slow Metro and hide cycles.

Unit tests

Tooling

  • jest-expo preset with @testing-library/react-native: one runner that handles the RN, Expo and .web.tsx transforms. Vitest would be quicker for the pure core but means maintaining two runners, which isn't worth it at this size.
  • Tests sit next to the code they test: ride.ts → ride.test.ts.
  • Scripts: "test": "jest", "test:watch", plus a check script that runs typecheck, lint and test together. A GitHub Action runs check on PRs (there's no CI yet).

No type-level tests. Strict TS with noUncheckedIndexedAccess already covers that. Fixtures come from real captured Ubian responses, so tests match what the API actually returns.

Migration — each step a behaviour-neutral PR

  1. Test harness + domain/. Add jest-expo. Move the pure helpers out of index.tsx, useTransitData.ts and LiveMap.web.tsx into src/domain, removing the duplicates. Write tests as they move. Removes roughly 600 lines from index.tsx.
  2. Move api/, server/, platform/. Mechanical moves; the proxy route ends up about 20 lines.
  3. UI primitives + theme. Extract ui/ and createThemedStyles.
  4. Feature components. Move departures, search, journey, ride, sheet and map into features/, one feature per commit.
  5. Split useTransitData into composed hooks, keeping its return shape so callers don't change.
  6. Screen reducer. The only step that changes how state is modelled, so it goes last, once the rest of the suite is in place.

Steps 1–5 move code without changing behaviour. Step 6 is a real refactor and gets its own review.
